发现 ① w₂ 与 JCT 存在反向关系
把 w₂（利用率）从 0.05 提高到 0.45，GPU 利用率从 88.5% 升至 92.2%，但平均 JCT 改善从 −20.4% 退化到 −1.2%。 原因是利用率奖励会引导任务向已饱和节点聚集，形成热点并加剧队头阻塞。
发现 ② 无静态权重可通吃全部指标
延迟优先在 JCT 上接近最优的 SJF，同时 GPU 利用率高出 0.8pt；吞吐优先占据利用率端点。 四组预设分别落在帕累托前沿的不同位置，不存在支配所有其他配置的单点。
发现 ③ → 强化学习的必要性论证
既然最优权重随负载特征变化（推理密集 vs 训练密集、大任务占比、队列深度）， 那么"根据实时集群状态在线选择权重"本身就是一个可学习的策略—— 这正是 PPO 在第二季度要解决的问题，而非简单调参。

简历项目经历 · 建议写法（STAR 结构）

HeteroNexus ｜ 异构算力协同调度平台 ｜ 核心开发 ｜ 2026.06 – 至今

S ｜ 高校与中小企业 GPU 集群平均利用率不足 40%，现有 K8s 调度器以静态分配为主，缺乏对异构硬件与多目标的联合优化。

T ｜ 设计一套插件化、无侵入的异构算力智能调度平台，在保证集群吞吐的前提下降低作业完成时间。

A ｜ ① 基于离散事件仿真自建集群调度仿真环境，复现 FIFO/DRF/BestFit/SJF 四类基线算法并完成 200 任务对比实验； ② 设计多目标奖励函数（JCT / 利用率 / 能耗 / 公平性 / 碎片），实现奖励驱动的调度策略与在线权重调节； ③ 设计基于 Kubernetes Scheduler Framework（Filter / Score / Permit / Reserve 扩展点）与 DRA 的调度插件方案， 并通过 gRPC 与 Python 侧决策服务解耦，支持启发式安全回退； ④ 构建集群数字孪生可视化控制台，实现调度过程实时回放与多算法指标对比。

R ｜ 仿真环境下 DRF 相较 FIFO 平均 JCT 降低 14.2%、中位 JCT 降低 54.3%； 多目标策略在保持 GPU 利用率 >90% 的同时进一步压缩长尾等待。相关代码已开源。
